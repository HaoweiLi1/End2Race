## 3. Red-green implementation order

### Task 1 — Lock constants and source boundary

Tests first:

- arm IDs are exactly `BC_FROZEN`, `SIDECAR_FROZEN`, and
  `SIDECAR_FINETUNE`;
- `K=10`, `Gamma=0.997^10`, `Lambda=0.99`, steer budget `0.2`, brake budget
  `1.0`, and positive speed budget `0.0` cannot drift through CLI overrides;
- common action-core LR is `3e-5`; C sidecar LR is `3e-6`;
- BC checkpoint, D2/D2R inputs, D2.5 full artifact, v2.2 spec, and plan hashes
  are pinned.

Release a source inventory before any remote execution.

### Task 2 — Implement exact macro accounting

Tests first:

- `K=1` matches current per-step discounted reward and GAE on synthetic and
  recorded trajectories;
- a ten-step full macro uses one action/log-prob/ratio and the hand-computed
  discounted aggregate;
- terminal macros of length 1–9 stop without padding or reward duplication;
- true collision termination has zero bootstrap;
- timeout and opponent-only truncation use the correct next critic values;
- recurrent hidden state advances at 100 Hz while the residual choice is held;
- episode reset clears BC, sidecar-history, macro, and critic state.

No simulator job runs until these unit tests pass locally and remotely in the
pinned interpreter.

### Task 3 — Implement the hurdle residual distribution

Tests first:

- deterministic initialization chooses exact `NO_OP` and zero steering;
- NO_OP log probability is the categorical atom only;
- BRAKE log probability is categorical plus conditional latent density;
- finite brake latents map bijectively to `(0,1.0)` m/s;
- steering maps to `[-0.2,+0.2]` radians;
- positive speed is structurally impossible;
- sampling, replay log probability, entropy, and KL agree independently;
- action composition/clipping is logged and any clipping fails a witness or
  policy-integrity gate.

### Task 4 — Implement A/B/C representation isolation

Tests first:

- all arms load the same frozen BC checkpoint and initial BC action sequence;
- A exposes only current frozen BC feature through its 128-dimensional
  adapter;
- B/C sidecar causal taps clamp within episode and use deployable signals only;
- B/C initialization state dicts are byte-identical;
- A/B BC parameters never receive gradients or mutate;
- B sidecar never receives gradients or mutates;
- C sidecar receives gradients at `3e-6` and changes after an update;
- all arms share byte-identical action-core initialization;
- immutable shadow diagnostic models never mutate in any arm.

Parameter-group manifests report every name, size, LR, trainable flag, and
initial/final SHA256.

### Task 5 — Produce the sidecar initialization release

Before fitting:

- append prospective `D3-R2-v2.2/actor_pretrain` registry rows for the 1,928
  reused non-test episodes;
- verify the D2 test seal and absence of test arrays/rows;
- pin the exact D2R-G source/config hashes used for the full-non-test fit;
- create a fresh output directory and refuse overwrite.

Run exactly one six-epoch full-non-test sidecar fit. Validate model shape,
finite outputs, causal inputs, source hashes, registry snapshot, and manifest.
Label the release `SIDECAR_INITIALIZATION_ONLY`; do not emit a D2R pass or
open a test.

### Task 6 — Lock witness/preservation warm-start data

Tests first:

- exactly the 67 independently rerun D2.5 confirmed-safe-pass witnesses are
  eligible positives;
- no clipped branch or exhausted case is labeled a positive;
- intervention macro ticks reproduce witness steer/brake commands;
- all other witness ticks are no-op residual labels;
- preservation episodes are corrected confirmed-safe-passes selected by one
  deterministic map/skill/raceline/L4-stratified hash rule;
- no preservation L2 duplicates a witness L2;
- no sealed-test or final-pool L2 appears;
- no privileged label field enters an actor input tensor;
- A/B/C consume identical ordered example IDs and labels.

Write and hash the warm-start manifest before fitting. Append registry reuse
under `D3-R2-v2.2/action_choice` without rewriting D2.5 rows.

Run a fixed-update warm-start smoke for all arms. Report losses and action
accuracy only as diagnostics. Do not select an arm.

### Task 7 — Implement separate objectives and dual constraint

Tests first:

- collision, ego-collision, terminal-overtake, confirmed-pass, and progress
  episode signals are stored separately;
- each critic sees only its intended target and actor gradients do not pass
  through privileged critic inputs;
- collision/performance advantages normalize independently;
- the dual starts at 1.0, is clamped to `[0,3]`, uses LR 0.5 and overtake-rate
  EMA coefficient 0.2, and does not update before 32 completed episodes;
- the normalized combined actor signal divides by `(1+lambda)`, retaining at
  least 25% collision weight at the cap;
- update ordering and state are deterministic, and dual transients are logged
  but never used alone to stop/select an arm;
- actor and critics expose separate pre/post-clip gradient norms;
- lexicographic selector rejects an overtake-inferior candidate even if its
  scalarized loss or collision count is lower;
- development overtake feasibility uses
  `lost-gained <= floor(0.01*N_gate)` per seed and pooled, not a zero-loss
  count gate;
- TTC and diagnostic alarms have no gradient path into reward, advantage,
  dual, or selector.

### Task 8 — Freeze training and development manifests

Generate one v2.2 manifest release from previously opened development data.
Selection rules may use map/raceline/speed/skill/L4 identities and fixed hashes;
outcome fields are used only to create explicitly labeled mechanism panels,
never to claim representative final performance.

Required panels:

- representative/preservation distribution;
- `skill_F`;
- `skill_S`;
- D2.5 witness-training cases, explicitly marked non-held-out;
- L4-disjoint recoverability diagnostic cases when available.

All A/B/C evaluation jobs are a byte-identical Cartesian product of the same
scenario manifest and arm/snapshot IDs. The release records which panels are
mechanism-enriched and which are distributional development estimates.

### Task 9 — No-learning and zero-residual simulator preflight

On a fresh fixed smoke manifest:

- replay BC and zero-residual A/B/C twice;
- require bit-identical actions, state arrays, outcomes, and terminal fields;
- require A/B/C results to match each other and BC;
- verify one macro action per ten micro-steps and correct short terminal macro;
- independently validate P0 result completeness and output hashes.

Any mismatch blocks warm-start deployment and PPO.

### Task 10 — Closed-loop warm-start evaluation

Evaluate deterministic warm-start checkpoints before PPO on the locked
development panels. Report actual paired collision/overtake/confirmed-pass
transitions and alarm/action/outcome joins. This is a diagnostic baseline, not
arm selection and not final evidence.

If every arm globally brakes, loses more overtakes than it gains, or clips
actions, stop before PPO and fix the shared action/warm-start implementation.
Do not tune TTC thresholds.

The first Task-10 artifact did trigger this stop and remains FAILED. Its
prospective remediation is a versioned four-coordinate hierarchical latent,
micro-step bound-preserving composition, folds-0--3 action-head refit, and
fold-4 negative-only episode calibration specified in v2.2 §6.3. Do not
mutate the historical model, checkpoint, Task-9, or Task-10 artifact.

Replacement execution order is load-bearing:

3. write a fresh fit/calibration manifest before fitting;

### Task 11 — Three-arm PPO pilot

Run A/B/C with identical:

- seed, scenario order, rollout length, PPO updates, macro settings;
- action distribution and budgets;
- warm-start examples and update count;
- reward/cost definitions, dual schedule, snapshot cadence;
- the same pooled `N_gate` used to translate the 1-point overtake tolerance
  into an integer paired-transition allowance;
- paired evaluation jobs.

Sequence:

1. seed 0 through 20 iterations;
2. evaluate every pre-registered snapshot once;
3. extend objective-aligned survivors to 40 iterations;
4. run seed 1 only for survivors;
5. independently validate and apply the v2.2 direct-outcome gate.

No arm is killed or promoted by TTC, Brier, alarm recall, training loss, or a
single seed.

### Task 12 — Select one arm or stop

For each arm and seed report:

- fixed/new any-agent and ego-involved collisions;
- gained/lost corrected terminal overtakes, `N_gate`, allowed net loss, and
  observed risk difference;
- collision-to-confirmed-pass transitions;
- safe-overtake retention;
- interaction-attempt change;
- map/skill/raceline/speed slices;
- alarm true/false, action/no-action, and outcome transitions;
- action clipping/saturation and residual exposure.

Reject any arm failing the spec's overtake/direct gate. Among survivors select
the largest paired net collision improvement; break an exact collision tie by
larger net overtake improvement, then earlier snapshot. Freeze at most one
medium candidate. If none survive, release a stop report and
diagnose the closed-loop failure without opening final data or returning
automatically to representation probes.

### Task 13 — Medium confirmation and one-open final boundary

Only the selected arm may run the locked 80–100 iteration, two-seed medium
confirmation. A passing medium release permits creation—not opening—of one
final candidate/model/jobs manifest. Final Austin/cross-map data remain sealed
until a separate preflight verifies zero overlap and the frozen checkpoint
hash. Final results are opened once and judged only by the v2.2 product gates.

## 5. Stop rules

Stop immediately on source/input hash drift, registry rewrite, sealed-test or
final-pool access, BC identity mismatch, episode-history leakage, nonfinite
loss/action, log-prob mismatch, frozen-parameter mutation, shadow-diagnostic
mutation, incomplete paired jobs, action clipping, manifest overlap, or
independent validation failure.

Policy-result stop rules are those in the v2.2 spec. A stopped policy stage
does not change the historical D2/D2R result and does not authorize a proxy
threshold change.
