## 4. Closed-loop corrected geometry

### 4.1 Centerline length

For each map, load `raceline1.csv` with delimiter `;`, `skiprows=1`, and use
columns 1 and 2 as binary64 `(x,y)`. Define the open-chain length

`L = sum(norm(xy[i+1]-xy[i]) for i=0..len-2)`.

No closing segment is added. This is the evaluator's formula.

### 4.2 Whole-series alignment

Use recorded arrays plus the appended terminal scalar:

1. unwrap ego and opponent independently by cumulative step deltas; if
   `d > L/2`, subtract L, and if `d < -L/2`, add L;
2. form `rel_raw = ego_unwrapped - opponent_unwrapped`;
3. choose the unique integer `k` with
   `rel_raw[0] + k*L in (-L/2, L/2]`;
4. apply that one constant `k*L` to every recorded and terminal element;
5. require aligned `rel[0] in (-L/2,0)` because ego starts strictly behind.

No per-frame re-anchoring is allowed. Failure of uniqueness or the anchor is
`alignment_failure`; all dependent fields are `unknown`, a ledger row is
written, and G7 blocks release.

The named regression fixture is
`eval_results/d2_c_seed2_local_off42_20260706_005227_Austin/overtake/o_ol1_e2095_o13_s0.5.npz`:
raw terminal relative progress `+417.1104679`, Austin open-chain L
`419.1146336`, corrected approximately `-2.0041657`.

### 4.3 Time and physics gates

Append `final_time`, `final_ego_pose`, `final_opp_pose`,
`final_ego_progress`, and `final_opp_progress` as the terminal frame.
`gap = final_time - time[-1]` must be positive and satisfy
`abs(gap-0.01) <= 0.005`. Every recorded consecutive time delta must be
positive and in `[0.005,0.015]`.

All trajectory arrays must have equal recorded length, finite numeric values,
and at least one recorded frame. The terminal frame is separate and must be
finite. A physics failure is a G6 violation.

### 4.4 Raw and normalized outcome fields

`archived_outcome_raw` is the verbatim `results.json` `outcome` string. It
must equal the verbatim `state_label` string and belong to exactly
`{following,overtaking,collision}`. Normalize only with:

```text
following  -> follow
overtaking -> overtake
collision  -> collision
```

The normalized field is `archived_outcome3`; it is never called verbatim.

`corrected_outcome3` is recomputed: `collision` iff
`ego_collision or opp_collision`; otherwise `overtake` iff corrected terminal
`rel > 0` strictly; otherwise `follow`.

`outcome_corrections.tsv` contains exactly the model/L2 rows where
`archived_outcome3 != corrected_outcome3`, no more and no fewer. Evidence
includes all source L1 IDs, raw and normalized labels, collision flags,
start/terminal relative progress, k, and both wrap counts.

## 5. Trajectory classifier `d0.1-traj-1`

### 5.1 Mechanism fields

- `interaction_attempt`: any recorded or terminal frame has `abs(rel)<=0.6`.
- `confirmed_safe_pass`: no collision and every selected frame in the closed
  time window `[final_time-0.7,final_time]` has `rel>=2.0`; the terminal frame
  is included. The nominal full window contains 71 frames.
- A non-collision trace spanning less than 0.7 seconds, or any physics/alignment
  failure, is `censored`. Collision episodes are never pass-censored and have
  `confirmed_safe_pass=false`.
- `attempted_follow_no_collision` is interaction attempt and safe follow.

Four-state classification is exact:

```text
any collision                                      collision
corrected overtake and confirmed_safe_pass         confirmed_pass
corrected overtake and not confirmed_safe_pass     terminal_overtake_only
corrected follow                                   safe_follow
```

Assert `confirmed_safe_pass => corrected_outcome3 == overtake`.

### 5.2 Collision event direct facts and inferences

There is one `collision_events.tsv` row per `(model_id,l2_id)` with any-agent
collision after G1 collapses equal occurrences.

Direct fields are `ego_collision`, `opp_collision`, and
`involvement in {ego_only,opp_only,both}`. Inferred fields are:

- `cause`: terminal ego/opponent Euclidean distance `<=1.0` m is `car`, else
  `wall`;
- `phase`: if `abs(terminal_rel)<0.6`, `alongside`; otherwise negative
  corrected terminal rel is `pre` and positive corrected terminal rel is
  `post`. Exactly `-0.6` is pre and exactly `+0.6` is post.

The row keeps `final_dist_hex`, `terminal_rel_hex`, classifier version, and a
representative L1 ID. Simulator flags are never overwritten by inference.

### 5.3 Released analytical record and G1 equality vector

For each L1 occurrence derive exactly this equality vector:

```text
archived_outcome_raw, archived_outcome3,
ego_collision, opp_collision, collision_any,
alignment_status, alignment_k, rel_start_hex, rel_terminal_hex,
```

Non-collision collision-classification fields use the literal `not_applicable`.
Unknown dependent fields use the literal `unknown`. G1 requires byte-equality
of every vector field across occurrences sharing `(model_id,l2_id)`; only then
may the lexicographically smallest L1 ID be selected as representative.

### 5.4 Transition matrices

For every candidate, estimand, pool, and requested stratum, emit the full 4x4
BC-four-state by candidate-four-state matrix in fixed row/column order
`collision,confirmed_pass,terminal_overtake_only,safe_follow`. All 16 cells,
including zeros, are present and sum to the exact scenario N.

Required strata are all, map, skill_F, skill_S, other, opponent raceline, and
speed bin. Parent anti-conservatism summaries are derived from these matrices.

## 6. Blocking and informational gates

- **G2 inventory (blocking):** expected RunConfig result directories and
  episode keys equal observed keys exactly; no missing, extra, duplicate,
  unvalidated, or stale merged result is allowed.
- **G3 source integrity (blocking):** every checkpoint, asset, `results.json`,
  and NPZ exists, is non-empty, stays under its configured root, and matches
  its recorded SHA256; every L1 is unique.
- **G4 near-duplicate sensitivity (informational):** compare only pairs with
  the same map, ego/opponent racelines, speedscale, and interval whose
  adjacent L3 starts are in one L4. Do not compare heterogeneous whole blocks.
- **G5 collision floors (blocking):** primary BC contains at least 30 distinct
  ego-involved collision L2 cases in both skill_F and skill_S.
- **G6 record/physics integrity (blocking):** terminal fields exist on all
  16,800 occurrences; raw JSON label rules, JSON/NPZ label agreement, collision
  Boolean identity, equal lengths, finiteness, time spacing, terminal gap, and
  exact scenario resolution all pass.
- **G7 unknown/censoring budget (blocking):** zero alignment failures and zero
  unknown fields are required. Any censored count greater than zero blocks the
  affected mechanism statistic and overall release until repaired; counts are
  always reported.
- **G8 relational reconciliation (blocking):** recompute rather than trust
  every cross-file count and set. Correction-ledger keys equal the exact
  archived/corrected mismatch set; collision-event keys equal the exact
  collision set; every transition matrix has 16 unique cells and correct sum;
  summary counts equal canonical rows; estimand IDs equal frozen S0 lists;
  SensA and SensB accounting is exact; provenance/input hashes, registry
  snapshot, and output manifest cover every released file. Omitted or extra
  correction rows, duplicate rows, or corrupted summary counts must fail G8.

Each gate emits `GateResult{name, blocking, passed, counts, violations}` with
stable sorted violations. `COMPLETE` is impossible unless the release gate
passes.

## 7. Statistical pre-registration

Point estimates are one vote per L2 scenario. For model m on a fixed pool:

```text
C_m = sum(1[four_state == collision])
O_m = sum(1[corrected_outcome3 == overtake])
RR_coll = C_candidate / C_BC
RD_coll = (C_candidate-C_BC)/N
RD_ot = (O_candidate-O_BC)/N
```

For each estimand (`primary,sensA,sensB`), candidate
(`cand040,cand120,cand160`), and pool (`all,austin,cross`), run a paired,
map-stratified L4 block bootstrap. Within each map resample its observed L4
blocks with replacement, retaining the observed block count; each drawn block
adds all member L2 rows with multiplicity. BC and candidate share the same
draw. Statistics are scenario-weighted ratio-of-sums over the expanded draw.

Use B=10,000 and `numpy.random.default_rng(20260710)`. Call `root.spawn(27)`
once and zip child generators to the Cartesian order: estimands in
`primary,sensA,sensB`; within each, candidates in
`cand040,cand120,cand160`; within each, pools in `all,austin,cross`.
Maps and L4 IDs are sorted lexicographically before draws.

Report percentile two-sided 95% intervals `[2.5,97.5]` and the one-sided 95%
upper percentile for RR. If observed BC collision count is zero, RR is
undefined and RD governs. Exclude zero-BC bootstrap replicates from RR
percentiles, report their fraction, and mark RR CI unstable if the fraction is
greater than 1%.

Same seed and inputs must produce byte-identical stats JSON. A changed seed
must change at least one non-degenerate replicate fingerprint.

## 12. Stage promotion

Stage 0 is source plus synthetic tests. Stage 1 is geometry and smoke. Stage 2
is the full scan and reconciliation. Stage 3 is registry/report integration
and D2 preparation. The user's unattended Goal authorizes automatic promotion
when the preceding technical gate passes; a failure is diagnosed and repaired
or routed according to the parent B+ stop rules, not paused for routine human
approval.
