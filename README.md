# End2Race: Efficient End-to-End Imitation Learning for Real-Time F1Tenth Racing

## Introduction

End2Race is an end-to-end imitation-learning framework for autonomous racing on the [F1Tenth platform](https://roboracer.ai/build). The actor learns temporal racing behavior from expert demonstrations generated by a Lattice Planner. This repository also contains a PPO fine-tuning pipeline that preserves the deployable End2Race actor while comparing four value-function designs.

## Environment Setup

### Requirements

- Python 3.10
- Linux for the validated PPO `forkserver` multiprocessing path
- CUDA-capable GPU recommended for training
- At least 4 CPU cores and 8 GB RAM

```bash
git clone https://github.com/HaoweiLi1/End2Race_PPO.git
cd End2Race_PPO
conda create --name end2race_ppo python=3.10 -y
conda activate end2race_ppo
bash install.sh
```

### Portable PPO artifacts

The repository keeps the models needed to continue development without publishing the full local experiment archive:

- canonical BC: `pretrained/end2race.pth`;
- current production U30: `post-trained/ppo_privilege_gru_clip020/update30/actor.pth`;
- selected first-action-preference U44 candidate: `post-trained/ppo_corridor_temporal_first_action_preference_v1/update44/actor.pth`.

The selected run configuration, metrics, episode records, scenario identities, and lightweight deterministic `results_multi.json` files are versioned with these actors. Raw numerical traces, critic checkpoints, intermediate actors, datasets, and superseded evaluation products remain excluded because they are large and are not required for deployment or result comparison. The decision record and evidence boundaries are in `.agents/HANDOFF.md` and `.agents/ANALYSIS.md`.

## Evaluation

### Single-agent evaluation

```bash
python eval_singleagent.py \
    --model_path pretrained/end2race.pth \
    --map_name Austin \
    --noise 0.0 \
    --render
```

- `--model_path`: End2Race actor checkpoint.
- `--map_name`: Track under `f1tenth_racetracks/`.
- `--noise`: Fraction of LiDAR points masked, from `0.0` to `1.0`.
- `--render`: Enable visualization and video recording.

### Multi-agent evaluation

```bash
python eval_multiagent.py \
    --model_path pretrained/end2race.pth \
    --map_name Austin \
    --ego_idx 150 \
    --interval_idx 15 \
    --opp_raceline raceline0 \
    --opp_speedscale 0.5 \
    --sim_duration 8.0 \
    --noise 0.0 \
    --render
```

The repository includes racelines for Austin, Hockenheim, MoscowRaceway, Nuerburgring, and other tracks. Each evaluated map must contain the requested raceline files.

### Parallel batch evaluation

```bash
MODEL_PATH=pretrained/end2race.pth \
COLLISION_SCOPE=ego \
RENDER=false \
SAVE_TRACE=false \
NUM_WORKERS=8 \
bash evaluate.sh
```

For a formal comparison, keep the model, scenario panel, collision scope, simulation duration, device, and worker topology fixed. Training-rollout episode counts are diagnostics and do not replace deterministic checkpoint evaluation.

```bash

    --batch_size 16
```

- `--mask_prob`: Probability of masking the speed input.
- `--batch_size`: Imitation-learning batch size.

## PPO Fine-Tuning

### Actor and observations

The deployable actor always receives 361 values:

```text
360 downsampled LiDAR ranges + previous measured ego speed
```

The `priviledge_mlp` and `privilege_gru` environments append 20 pre-action physical features, producing a 381D environment observation. The actor still slices and reads only the first 361 values. The privileged MLP reads only the final P20, while the hybrid critic sends the first 361 values through its independent recurrent branch and fuses the current P20 only at the value head. The CLI spelling `priviledge_mlp` is retained for compatibility.

### Critic variants

| CLI name | Critic input and structure |
|---|---|
| `mlp` | Current 361D actor observation through the copied BC pressure/speed preprocessing, then `420→60→ReLU→1` |
| `independent_gru` | Trainable BC-initialized pressure/speed/GRU critic with `1680→420→ReLU→1` value head |
| `priviledge_mlp` | P20 normalized pre-action physical state through `20→120→ReLU→30→ReLU→1` |
| `privilege_gru` | Independent GRU hidden plus a zero-initialized P20 projection, fused as `1680→420 + 20→420→ReLU→1` |

The P20 privileged features are:

```text
delta_s
relative_lateral
relative_long_velocity
relative_lat_velocity
sin_relative_heading
cos_relative_heading
ego_speed
ego_yaw_rate
relative_yaw_rate
obb_longitudinal_clearance
obb_lateral_clearance
wall_clearance
ego_steering_angle
ego_slip_angle
left_body_margin
right_body_margin
sin_track_heading_error
cos_track_heading_error
current_curvature
lookahead_mean_curvature
```

Relative velocity uses the simulator slip angle in the dynamic branch and the simulator-compatible low-speed kinematic branch.

### Start a run

Every output directory must be new or empty and must be inside `post-trained/`:

```bash
python train_ppo.py \
    --critic privilege_gru \
    --pretrained_model_path pretrained/end2race.pth \
    --output_dir post-trained/ppo_privilege_gru_0720
```

Current defaults are:

| Setting | Default |
|---|---:|
| logical environments / worker processes | `16 / 16` |
| rollout steps per environment | `6400` |
| transitions per rollout | `102400` |
| recurrent minibatch size | `12800` |
| formal updates | `30` |
| actor epochs / critic epochs | `2 / 5` |
| actor GRU LR / head LR / critic LR | `3e-6 / 3e-5 / 3e-4` |
| gamma / GAE lambda / clip range | `0.999 / 0.995 / 0.20` |
| steering latent std / speed physical std | `0.03 / 0.15` |

One extra rollout is collected before formal update 1 for critic-only warm-up. With `--num_updates N`, the run therefore collects `N+1` rollouts, writes one warm-up metrics row, then writes `N` formal metrics rows. Warm-up uses at most 30 epochs, 3-epoch early stopping, and a role-stratified 80/20 train/validation sequence split.

The actor trains only its GRU and output head. BC pressure preprocessing, the speed MLP, and fixed exploration standard deviations remain frozen. Actor and critic use separate optimizers.

### Scenarios and collision cache

Even logical environment slots use the collision role and odd slots use the ordinary role. Each role has one deterministic shuffled queue and visits every scenario in that role before reshuffling.

The collision role is built by running the canonical BC actor over 10,800 generated candidates. The default checked-in cache currently contains 479 ego-collision scenarios, 10,285 other outcomes, and 36 invalid reset/classification cases. A missing or empty cache directory is classified and populated. A partial or configuration-mismatched cache fails closed; use a new empty `--collision_cache_dir` when rebuilding is required.

The cache currently keys the pretrained model by path rather than file hash. Do not overwrite a model at the same path and reuse an old cache; either use a new cache directory or reclassify.

### Reward

The PPO reward is:

```text
0.01 × ego closed-track progress delta
+ 0.02 × relative progress delta
- 2.0 on the first ego collision
+ gamma × Phi(next_state) - Phi(current_state)
```

`Phi` is a bounded non-positive proximity potential over anisotropic vehicle-OBB clearance and the ego vehicle's map-wall clearance. Current thresholds are:

```text
longitudinal vehicle clearance: 0.6 m
lateral vehicle clearance:      0.2 m
wall clearance:                 0.2 m
maximum potential magnitude:    0.05
```

The potential term redistributes risk credit; it does not replace the terminal collision penalty.

### Run artifacts

```text
post-trained/<run>/
├── run_config.json
├── collision_scenarios.json
├── ordinary_scenarios.json
├── metrics.jsonl
├── episodes.jsonl
├── checkpoints/
│   ├── critic_warmup.pt
│   ├── actor_u0001.pth
│   ├── critic_u0001.pt
│   └── ...
```

`run_config.json` includes the resolved collision-pool source and scenario count. The two scenario files preserve the exact pools used by the run.

Every `actor_uXXXX.pth` is a strict-loadable original 12-key End2Race actor state dictionary. Critic checkpoints are training-only. Optimizer, environment, queue, and recurrent states are not saved, so the current pipeline does not provide exact interrupted-run resume.

Important formal-update metrics include:

- policy loss, value loss, critic epoch losses, KL, and clip fraction;
- episode count, mean episode length, and mean episode return;
- collision/ordinary role counts and mean returns;
- collision, overtake, follow counts and mean ego-collision time.

The episodes used by formal update `k` are collected before `actor_uXXXX.pth` for update `k` is written.

### Evaluate a PPO actor

```bash
MODEL_PATH=post-trained/ppo_priviledge_mlp_v2/checkpoints/actor_u0005.pth \
COLLISION_SCOPE=ego \
RENDER=false \
SAVE_TRACE=false \
NUM_WORKERS=8 \
bash evaluate.sh
```

Choose checkpoint evaluation times before inspecting results. Critic loss, explained variance, or training-rollout outcomes alone cannot identify the best deployable actor.
