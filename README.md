# End2Race: Efficient End-to-End Imitation Learning for Real-Time F1Tenth Racing

## Introduction

End2Race is an end-to-end imitation-learning framework for autonomous racing on the [F1Tenth platform](https://roboracer.ai/build). The actor learns temporal racing behavior from expert demonstrations generated by a Lattice Planner. This repository also contains a PPO fine-tuning pipeline that preserves the deployable End2Race actor while comparing five value-function designs.

## Environment Setup

### Requirements

- Python 3.10
- Linux for the validated PPO `forkserver` multiprocessing path
- CUDA-capable GPU recommended for training
- At least 4 CPU cores and 8 GB RAM

```bash

cd End2Race
```


## Evaluation

### Single-agent evaluation

```bash
python eval_singleagent.py \
    --model_path pretrained/end2race.pth \
    --map_name Austin \
    --noise 0.0 \
    --render
```

- `--model_path`: End2Race actor checkpoint.
- `--map_name`: Track under `f1tenth_racetracks/`.
- `--noise`: Fraction of LiDAR points masked, from `0.0` to `1.0`.
- `--render`: Enable visualization and video recording.

### Multi-agent evaluation

```bash
python eval_multiagent.py \
    --model_path pretrained/end2race.pth \
    --map_name Austin \
    --ego_idx 150 \
    --interval_idx 15 \
    --opp_raceline raceline0 \
    --opp_speedscale 0.5 \
    --sim_duration 8.0 \
    --noise 0.0 \
    --render
```

The repository includes racelines for Austin, Hockenheim, MoscowRaceway, Nuerburgring, and other tracks. Each evaluated map must contain the requested raceline files.

### Parallel batch evaluation

```bash
MODEL_PATH=pretrained/end2race.pth \
COLLISION_SCOPE=ego \
RENDER=false \
SAVE_TRACE=false \
NUM_WORKERS=8 \
bash evaluate.sh
```

For a formal comparison, keep the model, scenario panel, collision scope, simulation duration, device, and worker topology fixed. Training-rollout episode counts are diagnostics and do not replace deterministic checkpoint evaluation.

```bash

    --data_path Dataset_Austin \

    --hidden_scale 4 \
    --mask_prob 0.1 \
```

- `--data_path`: Demonstration dataset directory.

- `--hidden_scale`: GRU hidden-size multiplier.
- `--mask_prob`: Probability of masking the speed input.
- `--batch_size`: Imitation-learning batch size.

## PPO Fine-Tuning

### Actor and observations

The deployable actor always receives 361 values:

```text
360 downsampled LiDAR ranges + previous measured ego speed
```

The `priviledge_mlp` and `independent_gru_p20` environments append 20 pre-action physical features, producing a 381D environment observation. The actor still slices and reads only the first 361 values. The privileged MLP reads only the final P20, while the hybrid critic sends the first 361 values through its independent recurrent branch and fuses the current P20 only at the value head. The CLI spelling `priviledge_mlp` is retained for compatibility.

### Critic variants

| CLI name | Critic input and structure |
|---|---|
| `mlp` | Current 361D actor observation through the copied BC pressure/speed preprocessing, then `420→60→ReLU→1` |
| `detached_gru` | Actor GRU hidden stored and detached during rollout, then `LayerNorm→420→ReLU→1` |
| `independent_gru` | Trainable BC-initialized pressure/speed/GRU critic with `1680→420→ReLU→1` value head |
| `priviledge_mlp` | P20 normalized pre-action physical state through `20→120→ReLU→30→ReLU→1` |
| `independent_gru_p20` | Independent GRU hidden plus a zero-initialized P20 projection, fused as `1680→420 + 20→420→ReLU→1` |

The P20 privileged features are:

```text
delta_s
relative_lateral
relative_long_velocity
relative_lat_velocity
sin_relative_heading
cos_relative_heading
ego_speed
ego_yaw_rate
relative_yaw_rate
obb_longitudinal_clearance
obb_lateral_clearance
wall_clearance
ego_steering_angle
ego_slip_angle
left_body_margin
right_body_margin
sin_track_heading_error
cos_track_heading_error
current_curvature
lookahead_mean_curvature
```

Relative velocity uses the simulator slip angle in the dynamic branch and the simulator-compatible low-speed kinematic branch.

### Start a run

Every output directory must be new or empty and must be inside `post-trained/`:

```bash
python train_ppo.py \
    --critic independent_gru_p20 \
    --pretrained_model_path pretrained/end2race.pth \
    --output_dir post-trained/ppo_independent_gru_p20
```

Current defaults are:

| Setting | Default |
|---|---:|
| logical environments / worker processes | `16 / 12` |
| rollout steps per environment | `6400` |
| transitions per rollout | `102400` |
| recurrent minibatch size | `12800` |
| formal updates | `30` |
| actor epochs / critic epochs | `3 / 10` |
| actor GRU LR / head LR / critic LR | `1e-6 / 1e-5 / 1e-4` |
| gamma / GAE lambda / clip range | `0.999 / 0.995 / 0.10` |
| steering latent std / speed physical std | `0.03 / 0.15` |

One extra rollout is collected before formal update 1 for critic-only warm-up. With `--num_updates N`, the run therefore collects `N+1` rollouts, writes one warm-up metrics row, then writes `N` formal metrics rows. Warm-up uses at most 50 epochs, 5-epoch early stopping, and a role-stratified 85/15 train/validation sequence split.

The actor trains only its GRU and output head. BC pressure preprocessing, the speed MLP, and fixed exploration standard deviations remain frozen. Actor and critic use separate optimizers.

### Scenarios and collision cache

Even logical environment slots use the collision role and odd slots use the ordinary role. Each role has one deterministic shuffled queue and visits every scenario in that role before reshuffling.

The collision role is built by running the canonical BC actor over 10,800 generated candidates. The default checked-in cache currently contains 479 ego-collision scenarios, 10,285 other outcomes, and 36 invalid reset/classification cases. `--reclassify_collisions` rebuilds the cache and can take a long time. A partial or configuration-mismatched cache fails closed.

The cache currently keys the pretrained model by path rather than file hash. Do not overwrite a model at the same path and reuse an old cache; either use a new cache directory or reclassify.

### Reward

The PPO reward is:

```text
0.01 × ego closed-track progress delta
+ 0.02 × relative progress delta
- 2.0 on the first ego collision
+ gamma × Phi(next_state) - Phi(current_state)
```

`Phi` is a bounded non-positive proximity potential over anisotropic vehicle-OBB clearance and the ego vehicle's map-wall clearance. Current thresholds are:

```text
longitudinal vehicle clearance: 0.6 m
lateral vehicle clearance:      0.2 m
wall clearance:                 0.2 m
maximum potential magnitude:    0.05
```

The potential term redistributes risk credit; it does not replace the terminal collision penalty.

### Run artifacts

```text
post-trained/<run>/
├── run_config.json
├── collision_cache_info.json
├── collision_scenarios.json
├── ordinary_scenarios.json
├── metrics.jsonl
├── episodes.jsonl
├── checkpoints/
│   ├── critic_warmup.pt
│   ├── actor_u0001.pth
│   ├── critic_u0001.pt
│   └── ...
└── actor_final.pth
```

`actor_final.pth` and every `actor_uXXXX.pth` are strict-loadable original 12-key End2Race actor state dictionaries. Critic checkpoints are training-only. Optimizer, environment, queue, and recurrent states are not saved, so the current pipeline does not provide exact interrupted-run resume.

Important formal-update metrics include:

- overall pre/post value loss and explained variance;
- collision-role and ordinary-role pre/post value loss and explained variance;
- critic epoch losses, prediction/return scale, gradients, KL, and clip fraction;
- per-role episode return and relative position;
- progress, relative, collision, and risk reward components;
- OBB/wall clearance and risk-activation telemetry;
- normalized privileged-feature statistics for `priviledge_mlp`.

The episodes collected for formal update `k` were generated by actor checkpoint `k-1`; `metrics.jsonl` records this explicitly as `rollout_policy_update` and `checkpoint_update`.

### Evaluate a PPO actor

```bash
MODEL_PATH=post-trained/ppo_priviledge_mlp_v2/checkpoints/actor_u0005.pth \
COLLISION_SCOPE=ego \
RENDER=false \
SAVE_TRACE=false \
NUM_WORKERS=8 \
bash evaluate.sh
```

Choose checkpoint evaluation times before inspecting results. Critic loss, explained variance, or training-rollout outcomes alone cannot identify the best deployable actor.
