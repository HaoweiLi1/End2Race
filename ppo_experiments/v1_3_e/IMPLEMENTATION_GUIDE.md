# End2Race PPO V1.3-E CPU Evaluation Correction

## 1. Purpose

V1.3-E is an evaluation-only continuation of V1.3-D. It does not train another
actor and does not change any PPO hyperparameter.

V1.3-D correctly stopped with `STOP_PROTOCOL_DRIFT`: its fresh BC evaluation
ran on CUDA and produced `22 collision / 234 follow / 344 overtake`, while the
locked reference `21/233/346` was generated by the historical V1.2 evaluator
with `EVALUATION_DEVICE = torch.device("cpu")`.

The only correction in V1.3-E is to force every evaluation worker onto CPU by
setting `CUDA_VISIBLE_DEVICES=""`. The three fixed V1.3-D U8 actors, the 600
Austin scenarios, and all product thresholds remain unchanged.

This continuation is explicitly exploratory because it was designed after the
V1.3-D device mismatch was observed. It cannot promote a model or consume a
holdout.

## 3. Frozen evaluation contract

```text
device             = CPU (`CUDA_VISIBLE_DEVICES=""`)
map                = Austin
collision_scope    = ego
workers            = 4
num_startpoints    = 50
ego_idx_offset     = 0
noise              = 0.0
sim_duration       = 8.0
render             = false
save_trace         = false
episodes           = 600
unique scenarios   = 600
error              = 0
```

No evaluation may be retried, merged, repaired, or partially reused.

## 4. Execution order

1. Copy BC and the three fixed candidates to their unique V1.3-E basenames and
   verify SHA-256 plus strict 12-key loading.
2. Evaluate the BC once on CPU.
3. Require exact BC counts `21 collision / 233 follow / 346 overtake / 0 error`.
4. If and only if the BC gate passes, evaluate the three candidates serially in
   seed order `20260735, 20260736, 20260737`.
5. Run `ppo_experiments/v1_3_e/aggregate_results.py` once all required outputs
   exist.

Every evaluation command must start its log with `EVAL_DEVICE=cpu` and use:

```bash
CUDA_VISIBLE_DEVICES="" \
MODEL_PATH=<checkpoint> \
COLLISION_SCOPE=ego \
RENDER=false \
SAVE_TRACE=false \
NUM_WORKERS=4 \
NUM_STARTPOINTS=50 \
EGO_IDX_OFFSET=0 \
NOISE=0.0 \
SIM_DURATION=8.0 \
bash evaluate.sh
```

## 5. Locked product gate

For every one of the three fixed candidates, pair rows by scenario ID against
the fresh CPU BC and require all of:

```text
G = fixed_collision - new_collision >= 5
candidate collision <= 16
candidate overtake >= 340
mean speed ratio to BC >= 0.99
mean distance ratio to BC >= 0.99
```

The cross-seed gate is `3/3`. Mean, median, or a best seed cannot replace it.

## 6. Terminal verdicts

- `PASS_EXPLORATORY_CPU_DEVELOPMENT`: BC matches and all three candidates pass
  every product gate. This only authorizes a separately preregistered new
  holdout; it does not authorize selection or promotion.
- `FAIL_NO_STABLE_IMPROVEMENT`: at least one fixed candidate fails a product
  gate. The physical-Gaussian repair stabilized PPO updates but did not produce
  the required cross-seed driving improvement.
- `STOP_CPU_BASELINE_MISMATCH`: the CPU BC does not reproduce `21/233/346`.
- `INVALID_EVALUATION`: missing, malformed, non-600-row, non-ego, nonfinite, or
  otherwise invalid evaluation evidence.

In every verdict:

```text
selection_performed = false
holdout_performed = false
promotion_performed = false
canonical BC remains the deployment recommendation
```
